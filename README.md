# نظام إدارة فريق السوشال ميديا

تطبيق Next.js كامل لإدارة فريق سوشال ميديا يخدم عدة شركات — من **التخطيط → الكتابة →
التصميم/التصوير → النشر** — مع جدولة تلقائية، لوحة Kanban، تقويم نشر، أحمال عمل،
تقارير إنجاز، و**قسم مالية** لربح/خسارة كل عقد. الواجهة عربية **RTL** بتيمة فاتحة.

> 📖 التوثيق الكامل للنظام (المعمارية، القواعد، نموذج البيانات) في
> [`PROJECT.md`](./PROJECT.md). هذا الملف مقدّمة سريعة فقط.

## المتطلبات

- Node.js 18+ (يفضل 20)
- npm

## التثبيت السريع

```bash
cd sm-team-dashboard
npm run setup        # install + prisma generate + db push + seed
npm run dev
```

افتحي [http://localhost:3000](http://localhost:3000).

## أوامر مفيدة

| الأمر | الوظيفة |
|-------|---------|
| `npm run dev` | تشغيل التطوير (SQLite) |
| `npm test` | الاختبارات (Vitest — 85 اختبار) |
| `npm run typecheck` | فحص الأنواع (tsc) |
| `npm run db:seed` | زرع البيانات (غير هدّام — يزرع الشهر الفارغ فقط) |
| `npm run db:studio` | فتح Prisma Studio |
| `npm run db:push` | تطبيق الـ schema على قاعدة البيانات |

## نسخة احتياطية قبل التعديلات الكبيرة

قاعدة البيانات المحلية ملف واحد: `prisma/dev.db`. قبل أي تعديل كبير (إعادة جدولة
واسعة، تغيير خطط، إعادة زرع) خذي نسخة احتياطية بنسخ الملف:

```bash
# نسخة مؤرّخة
cp prisma/dev.db "prisma/dev.backup-$(date +%Y%m%d-%H%M).db"

# للاسترجاع: أوقفي الخادم ثم استبدلي الملف
# cp prisma/dev.backup-YYYYMMDD-HHMM.db prisma/dev.db
```

> `إعادة الجدولة` و`db:seed` غير هدّامين (يحفظان تعديلاتك اليدوية والبيانات
> الموجودة)، لكن النسخة الاحتياطية تبقى أأمن خيار قبل التغييرات الكبيرة.

## أهم المميزات

1. **خط إنتاج (Pipeline) + Kanban** — كل محتوى يمر: كتابة → تصميم/تصوير → نشر، كل
   مرحلة كارت على لوحة الشخص، وكل قطعة محتوى كارت مستقل مُرقَّم (لا تجميع للبوستات
   أو الستوريز): بوست-1، ستوري-2، ريل-1، ريل AI-3.
2. **جدولة تلقائية ذكية** — توزيع المحتوى على الشهر مع احترام أيام عمل كل شخص وطاقته
   الإنتاجية، وزر **إعادة الجدولة** يحفظ تعديلاتك وحالات المهام.
3. **دورات العقود** — كل شركة توزّع خطتها على دورة 30 يوماً من تاريخ توقيع العقد
   (مثلاً من 20 لـ 20)، لا من أول الشهر الميلادي.
4. **عدة مصوّرين** — توزيع ريلز كل شركة على المصوّر المختار، مع جدولة نزلات التصوير
   على أيام عمل كل مصوّر.
5. **أحمال عمل (Burndown)** — حِمل مخطّط (مطلوب/منجز/متبقّي/متاح) لكل موظف.
6. **تقارير الإنجاز** — لكل شخص مهامه (بداية/نهاية/مدة فعلية/تأخير)، وإنجاز خطة كل
   شركة (يُحتسب فقط عندما تكون مرحلة الإنتاج ومرحلة النشر منجزتين).
7. **المالية** — ربح/خسارة كل عقد (تكلفة موزّعة حسب أيام العمل)، أقل عدد عقود لتغطية
   الأجور، وكم عقداً يتّسع له الفريق.
8. **قواعد التأخير مثبتة** — المهمة المتأخرة هي فقط: غير منجزة، وتجاوزت موعد
   التسليم/النشر. المهام المنجزة لا تظهر كمتأخرة حتى لو تاريخها قديم.

## ملاحظات

- قاعدة SQLite في `prisma/dev.db` — النسخ الاحتياطية في `backups/`.
- الفريق الأولي: أيمن، سابين، حلا، نوال، عمر، المصوّر (6) + 9 شركات.
- الزرع **غير هدّام**: لا يمسح بياناتك؛ لإعادة بناء كاملة استخدمي `SEED_FORCE=1`.

### القاعدة ٦ — مَحسومة

**[USER-CONFIRMED] (١/٩)** «بدي ياه علامة على *مهام اليوم* لكل شخص».

`urgent` **وسم عرض، لا سلوك جدولة**. المحرّك لا يُمَس: لا يكسر السقف اليومي ولا
يعيد الترتيب. هو إخبار للشخص أن هذه القطعة تحديداً ضيّقة الوقت — تُسلَّم قبل
النشر بيوم لا بيومين — فيعرف أين ينتبه في يومه.

ملاحظة تمييز: `Priority.URGENT` القائم شيء آخر تماماً (أولوية تعطي ASAP في
`scheduler.ts` §5.4). الوسم الجديد **مشتقّ من التواريخ** لا من حقل مخزَّن، فلا
يحتاج هجرة قاعدة بيانات ولا يمكن أن يتناقض مع الواقع.

## ٢. النطاق

**داخل النطاق**
1. بناء جدول نشر لشركة واحدة ضمن دورة نشرها الحالية.
2. صفحة عرض للطباعة + تصدير PDF.
3. تذكير يومي على تلغرام لكل شركة لها نشر اليوم/غداً.

**خارج النطاق** (لا تُنفَّذ بلا طلب صريح)
- تعديل محرّك الجدولة أو مهل التسليم.
- تغيير أي داتا إنتاج.
- جدول موحّد لكل الشركات (الطلب: شركة شركة).

## ٣. القرار التقني الحاسم — كيف يُولَّد الـPDF

**التوصية: صفحة HTML مصمَّمة للطباعة + «حفظ PDF» من المتصفح.**

السبب: العربية في مكتبات PDF كابوس — تحتاج تشكيل حروف (shaping) واتجاه RTL
وتضمين خط. `pdfkit` و`jspdf` تُخرج حروفاً مقطّعة ومعكوسة بلا عمل ثقيل. المتصفح
يحل الثلاثة مجاناً وبإتقان.

- بلا اعتماديات جديدة، وبلا مخاطر حجم على Vercel.
- المخرج PDF حقيقي قابل للإرسال، والطباعة الورقية تعمل أيضاً.
- الخط: `@page` بحجم A4 و`print-color-adjust: exact`، وخط عربي مضمَّن أو
  Google Font مع بديل واضح.

**البديل المرفوض:** headless Chromium على Vercel — حجم الحزمة والوقت البارد
لا يستحقان، والمخرج نفسه.

**إن أصرّت القائدة على PDF يُولَّد على الخادم** (مثلاً ليُرسَل كملف على تلغرام
بلا تدخل بشري): عندها الخيار الواقعي هو توليد الجدول كصورة PNG عبر Canvas ثم
إرسالها، أو خدمة تحويل خارجية — وكلاهما قرار منفصل يُعرض عليها.

## ٤. المراحل

### المرحلة ١ — وحدة البناء النقيّة (لا واجهة، لا شبكة)

ملف جديد: `src/lib/publishing-schedule.ts`

```ts
export type ScheduleRow = {
  dayName: string;        // «الأحد»
  date: Date;
  iso: string;            // 2026-09-07
  type: ContentType;      // POST | REEL | AI_REEL | STORY
  typeLabel: string;      // «بوست»
  pieceNo: number | null;
  assetName: string | null;   // «Wasl 9-3» — نفس تسمية الكروت
  owner: string | null;       // اسم الناشر
  status: string;             // منشور / جاهز / قيد الإنتاج / متأخر
  deliverBy: Date | null;     // موعد تسليم الإنتاج
  leadDays: number | null;    // الفرق بين التسليم والنشر
  urgent: boolean;            // leadDays < 2  (القاعدة ٥)
};

export type CompanySchedule = {
  companyName: string;
  cycle: { start: Date; end: Date } | null;  // end حصري
  rows: ScheduleRow[];
  warnings: string[];   // «قطعة خارج نافذة الدورة» …
};

export function buildCompanyPublishingSchedule(
  company: Company,
  tasks: Task[],
  employees: Employee[],
  today: Date,
): CompanySchedule;
```

قواعد البناء:
- الدورة من `cycleForBucket` / `publishStartDate` — **لا تُحسب من تاريخ العقد** (القاعدة ٣).
- تُدرج كروت `stage === "PUBLISH"` فقط، مرتّبة بالتاريخ ثم بالنوع.
- `deliverBy` = `readyDate` لكرت الإنتاج المقابل (نفس `pipelineKey`).
- `urgent` = `leadDays < 2` (القاعدة ٥). هذا **وصف للواقع**، لا تغيير له.
- أي صف خارج نافذة الدورة يُدرج في `warnings` ولا يُحذف (القاعدة ٤ تُكشف، لا تُخفى).

**اختبارات** `tests/publishing-schedule.test.ts` — على تجهيزات اصطناعية لا على
`dev.db`، فتبقى صالحة مهما تغيّرت الداتا:
1. الصفوف مرتّبة تصاعدياً بالتاريخ.
2. الدورة تُشتق من أول نشر لا من تاريخ العقد (شركة تاريخ عقدها ١٣/٧ ونشرها ٢٠/٧ → الدورة تبدأ ٢٠/٧).
3. النافذة ٣٠ يوماً ونهايتها حصرية.
4. قطعة نشرها خارج النافذة تُنتج تحذيراً ولا تختفي.
5. `urgent` يُرفع عندما التسليم قبل النشر بيوم، ولا يُرفع عند يومين.
6. أسماء الأيام عربية وصحيحة لأيام معروفة.
7. شركة بلا دورة (بانتظار التجديد) → `cycle: null` وجدول فارغ بلا انهيار.
8. الحالة تُشتق من الكرت لا تُخمَّن (منشور/جاهز/متأخر).

### المرحلة ٢ — صفحة العرض والطباعة

مسار جديد: `src/app/admin/companies/[id]/schedule/page.tsx`
(داخل `/admin` فيرثه حارس الجلسة القائم — تحقّق أن الـmiddleware يغطيه.)

- زر في صفحة الشركات: **«جدول النشر»** بجانب «استيراد خطة».
- الصفحة: ترويسة (اسم الشركة، نافذة الدورة، عدد القطع حسب النوع)، ثم جدول
  **اليوم · التاريخ · نوع المحتوى · القطعة · التسليم · الحالة**.
- وسم `urgent` يظهر كشارة على الصف.
- التحذيرات (القاعدة ٤) تظهر أعلى الجدول بلون تنبيه.

**اختبارات** `tests/publishing-schedule-page.test.ts`: اختبار حدود بلا متصفح —
أن الصفحة تتطلب صلاحية إدارة، وأن شركة غير موجودة تعطي 404 لا انهيار.

### المرحلة ٣ — التذكير اليومي على تلغرام — **مؤجّلة بقرار القائدة (١/٩)**

> «التذكير الخاص اتركه هلق، بدنا نعدّل بالتقارير.» لا تُنفَّذ هذه المرحلة قبل
> أن تُحسم صيغة التقارير. ما تحتها محفوظ للتنفيذ لاحقاً كما هو.

**قيد حاسم:** خطة Vercel المجانية تؤخّر الكرون حتى ساعة، والمشروع فيه أربعة
كرونات أصلاً. **لا تُضَف مهمة كرون لكل شركة.** يُضاف كرون واحد يلفّ على الشركات.

- وحدة نصّية نقيّة: `buildCompanyReminder(schedule, today) → string | null`
  - `null` إذا لا يوجد نشر اليوم ولا غداً (لا تُرسل رسالة فارغة).
  - النص: «مانغو — اليوم الاثنين ٧/٩: بوست ٣. بكرا: ريل ٤ (تسليمه اليوم ⚠️).»
  - القطعة المتأخرة إنتاجها تُذكر صراحة — التذكير أداة إنذار لا تقويم.
- الإرسال: يُعاد استخدام `src/lib/telegram/service.ts` ووجهته خاصّ القائدة
  (نفس قاعدة المشروع: لا شيء آلي ينزل في مجموعة عميل).
- مسار: `src/app/api/cron/publish-reminders/route.ts` — **fail-closed** على
  `CRON_SECRET` مثل باقي الكرونات (503 بلا سر، 401 بسر خاطئ).
- `vercel.json`: مدخل واحد جديد.

**اختبارات** `tests/publishing-reminder.test.ts`:
1. لا نشر اليوم ولا غداً → `null` (ولا رسالة).
2. نشر اليوم → يُذكر بالاسم والنوع.
3. نشر غداً وإنتاجه غير جاهز → تحذير صريح.
4. عدة شركات → رسالة لكل شركة، وفشل واحدة لا يوقف البقية (نفس درس البريف).
5. حدود المسار في `tests/http-boundaries.test.ts`: 503 / 401 / 200.

### المرحلة ٤ — وسم `urgent` على «مهام اليوم»

**[USER-CONFIRMED]** المطلوب: علامة على كرت العمل في «مهام اليوم» لكل شخص، حين
تكون مهلة تسليمه أقل من يومين قبل النشر.

**مصدر واحد للحقيقة.** نفس الحساب يلزم في جدول النشر (المرحلة ١) وفي «مهام
اليوم»، فيُكتب مرة واحدة في `src/lib/delivery-lead.ts`:

```ts
/** أيام المهلة بين تسليم كرت الإنتاج ونشر قطعته. null إذا لا نشر مقابل. */
export function deliveryLeadDays(
  task: Task,
  publishByPipelineKey: Map<string, Task>,
): number | null;

/** ضيّقة الوقت: تُسلَّم قبل النشر بيوم لا بيومين (القاعدة ٥). */
export function isUrgentDelivery(leadDays: number | null): boolean;
```

- يُطبَّق على مراحل الإنتاج فقط: `DESIGN` · `SHOOT` · `EDIT`.
- المهلة = `publishDate` ناقص (`readyDate ?? workDate`).
- `urgent` عندما `leadDays !== null && leadDays < 2`.
- الكرت المنجز لا يُوسَم — الوسم تنبيه لعمل قادم، لا حكم على ما مضى.

**نقطة الربط في الواجهة:** `src/app/overview-client.tsx` — قسم «مهام اليوم»
(السطر ~٤٨٥، مصدره `selectDailyWorkTasks` بالسطر ~١٨٧). تُضاف شارة صغيرة على
الصف. **لا يُلمس ترتيب الاختيار ولا حساب الحمل** — عرض فقط.

**اختبارات** `tests/delivery-lead.test.ts`:
1. مهلة يومين → لا وسم. مهلة يوم → وسم. مهلة صفر أو سالبة → وسم.
2. كرت بلا كرت نشر مقابل → `null` ولا وسم (لا ينهار).
3. كرت منجز → لا وسم مهما كانت المهلة.
4. مراحل النشر والكتابة لا تُوسَم — الوسم للإنتاج فقط.
5. `readyDate` غائب → يُستعمل `workDate` بديلاً.
6. اختبار تكامل خفيف: قطعة ضيّقة تظهر موسومة ضمن مخرجات «مهام اليوم» لشخص.

### نتيجة المحاكاة — ١/٩ على نسخ معزولة (ما انلمس لا الإنتاج ولا الداتا المحلية)

أربع نسخ من `prisma/dev.db`، وإعادة توليد **كل دلو مفتوح** (آب · أيلول · ت١)
مرتين لكل سيناريو. تشغيل ضابط بالثوابت الحالية أعاد إنتاج الحالة المخزّنة **بايت
ببايت** (٠ من ١٠٩٨ كرت تغيّر) — فكل رقم تحت منسوب للتغيير نفسه لا لضجيج التوليد.
بصمة الداتا الأصلية `563799…8744e` نفسها قبل وبعد.

**اكتشافان بيغيّرا الخطة:**

1. **`LEAD.REEL` ما بيجدول المونتاج أصلاً.** `pipeline.ts` بيأرّخ كرت المونتاج من
   تسليم التصوير، لا من `publishDate − LEAD.REEL`. و`PHOTO_SHOOT_LEAD` ما بينقرا
   إلا في أرضية النشر للدورة الأولى (`scheduler.ts:297`). يعني ١٢ من الـ١٤ مخالفة
   (كلها مونتاج ريل) **ما بتتصلّح برفع الثابت** — بدها تعديل في مسار الريل
   (المونتاج ≥يومين قبل النشر، والتصوير ≥٢–٣ أيام قبل المونتاج) مع اختباراته.
2. **ثلاثة أرقام لطاقة المصمّم في ثلاثة أماكن**: المحرّك بيسمح **١٠/يوم**
   (`hoursPerDay 8 ÷ TYPE_HOURS 0.8`)، وشاشة الحمل بتقول **٨/يوم** (معدّل الموظف)،
   وقاعدة القائدة **٦/يوم**. خفضها لـ٦ تصحيح تقارير أكتر منه تغيير جدولة.
3. قيد المصوّر: ماجد ما بيتجاوز ٣ شركات/يوم ولا مرة (كل يوم تصوير شركة وحدة)، بس
   **٤ أيام فيها ٣ ريلات لنفس الشركة** (التوظيف ٢/٩ · ١٦/٩ · ٣٠/٩ · ١٤/١٠) —
   يعني قيد «≤٢ لكل شركة» بيشتغل فعلياً على هالأيام الأربعة.

**حدّ المحاكاة:** النسخة المحلية تاريخها ٢٦/٨ وما فيها دورة وصل الأيلولية (٤٣ قطعة
منها ٢٠ ستوري) لأنها انستوردت على الإنتاج مباشرة. ستوريات وصل بالضبط هي النوع
اللي بينزاح، فرقم الـ٢٦ على الحي أعلى.
